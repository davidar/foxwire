# Firefox WebExtension MCP drivers for Claude Code — survey (3 Oct 2026)

This survey was made before foxwire was written. It recommended trying FoxPilot; foxwire was written instead, on the same architecture (see the "What would flip it" notes at the end and `WHY-NOT-WEBDRIVER.md`). Numbers and versions are as of the survey date.

Read-only research. Nothing installed. Repos were shallow-cloned locally for source reading; AMO numbers come from the AMO v5 API (`https://addons.mozilla.org/api/v5/addons/addon/<slug>/`). GitHub numbers from `gh api repos/<owner>/<repo>` on 3 Oct 2026. npm numbers from `registry.npmjs.org` + `api.npmjs.org/downloads/point/last-month/`.

The target machine (the author's; Fedora, Firefox Flatpak `org.mozilla.firefox` 157.0). The Flatpak has `shared=network` (so it shares the host loopback: any localhost-WebSocket design works with zero sandbox friction) and **no** `org.freedesktop.NativeMessagingProxy` talk permission (so native-messaging designs do not work out of the box — see §Flatpak).

## 1. FoxPilot — recommended

- **AMO**: https://addons.mozilla.org/en-US/firefox/addon/foxpilot/ — signed (listed). 25 daily users, 4.0 from 1 review, version 1.0.22 released 2026-08-08, created 2026-06-12, compat Firefox ≥ 58, licence MIT ([AMO API](https://addons.mozilla.org/api/v5/addons/addon/foxpilot/)). AMO lags the repo: repo `firefox-extension/manifest.json` is 1.0.28.
- **Owner**: Bala Kumar (individual) ([README](https://github.com/balakumardev/foxpilot)). Source: https://github.com/balakumardev/foxpilot — MIT, 11 stars, last push 2026-10-02, ≥100 commits since 2026-06-12 (`gh api repos/balakumardev/foxpilot/commits`). The README text and permission model are lifted from eyalzh's Browser Control MCP (identical wording); GitHub does not mark it as a fork. Repo carries `docs/superpowers/` plan files, i.e. heavily AI-assisted development with high churn.
- **npm**: `foxpilot-mcp` 1.0.28 published 2026-10-02, 21 versions, **zero runtime dependencies**, no install scripts, 333 downloads last month ([registry](https://registry.npmjs.org/foxpilot-mcp)).
- **Architecture**: MCP server (stdio to Claude Code) runs a local WebSocket broker on 127.0.0.1:8089; the extension connects to it. No cloud, no account, no PRO tier. Pairing is "zero-config": the broker admits any connection with a `moz-extension://`/`chrome-extension://` Origin (`mcp-server/broker.ts:56`, `:498`; "Empty/undefined accepts any chrome-/moz-extension origin", `:139`). Setting `EXTENSION_SECRET` in both server env and extension options switches to HMAC-signed pairing (README "Migration" + "Docker" sections). Optional `input-sidecar` (nut-js native input) exists for OS-level trusted input; built for macOS per `CLAUDE.md:78`, Wayland behaviour unverified.
- **Permissions (AMO)**: required `tabs, tabGroups, history, storage, cookies, webRequest, webRequestBlocking, http://localhost/*, http://127.0.0.1/*`; optional `<all_urls>, find`; data collection `none`. No persistent `content_scripts` in the manifest. Nothing phones home in the extension per README ("No runtime third-party dependencies", local-only); I did not find outbound URLs beyond localhost in the Firefox manifest permissions.
- **Tool surface** (README "Features"): tabs/windows (open, close, reorder, group, list, active tab, resize), history search, page text+links, find/highlight, **accessibility snapshot with stable uids**, navigate/back/forward, wait-for-text; Automation Mode (opt-in): click, hover, fill, fill form, type, press key, drag, **file upload**, **evaluate JS**, screenshots (viewport/full/element), console + network capture, dialog handling, geolocation/UA emulation. That is close to the Playwright MCP set (`browser_snapshot`/`click`/`type`/`fill_form`/`file_upload`/`evaluate`/`take_screenshot`/`console_messages`/`network_requests`/`handle_dialog`/`tabs`/`navigate`), minus PDF save.
- **Detectability**: no content script on pages by default; code is injected per action via `executeScript`. Console capture, when used, hooks the page console in the main world and sets `window.__bcmcpConsoleHooked` (`firefox-extension/console-capture.ts:300`) — page-visible only while you use that tool. No `navigator.webdriver`, no remote-control icon. Clicks are synthetic DOM events (`isTrusted=false`) unless the sidecar is used — Turnstile's interactive checkbox still needs a human click; passive Cloudflare checks see a normal browser. The author has a dedicated design doc for driving `dash.cloudflare.com` (`docs/superpowers/specs/2026-07-08-foxpilot-cloudflare-fixes-design.md`), i.e. it is exercised on Cloudflare-fronted SPAs.
- **Firefox/Flatpak**: MV2, gecko id `foxpilot@balakumar.dev`, AMO compat ≥ 58. Localhost WS only → works in the Flatpak as-is (`shared=network`).
- **Claude Code setup**: README documents the JSON config (`"command": "npx", "args": ["-y","foxpilot-mcp"], "env": {"EXTENSION_PORT":"8089"}`). Equivalent CLI (my translation, pin the version):
  `claude mcp add foxpilot -e EXTENSION_PORT=8089 -e EXTENSION_SECRET=<secret> -- npx -y foxpilot-mcp@1.0.28`
  then set the same secret in the add-on's options, grant `<all_urls>` (or per-domain), and switch on Automation Mode.
- **Known issues**: [#4](https://github.com/balakumardev/foxpilot/issues/4) (open, 2026-09-10) "get-list-of-open-tabs caused the browser extension connection to disconnect". Upstream eyalzh [#66](https://github.com/eyalzh/browser-control-mcp/issues/66) (open, 2026-09-28) "Untrusted apps can receive browser commands, and disabled tools can turn back on" — check whether it applies to the fork before relying on per-tool toggles.

## 2. Claudezilla

- **AMO**: https://addons.mozilla.org/en-US/firefox/addon/claudezilla/ — signed. 296 users, 5.0 (1 rating, 0 text), 0.7.0 released 2026-09-09, compat ≥ 140, MIT ([AMO API](https://addons.mozilla.org/api/v5/addons/addon/claudezilla/)).
- **Owner**: Boot Industries (GitHub org) — https://github.com/boot-industries/claudezilla, MIT, 39 stars, last push 2026-08-07, 12 open issues. Homepage https://claudezilla.com/.
- **Architecture**: `Claude Code ←→ MCP Server ←→ Unix Socket ←→ Native Host ←→ Firefox Extension` (README "Architecture"). Socket auth token generated at host start (`host/index.js:50`). Not on npm; install = `git clone` + `./install/install-linux.sh`, which writes the host manifest to `$HOME/.mozilla/native-messaging-hosts` (`install-linux.sh:15`), runs `npm install`, and **edits `~/.claude/mcp.json` itself** (README "Quick Start"). No Flatpak handling anywhere in the repo. Extension only calls out to `https://api.claudezilla.com` for the optional Stripe donation checkout (`extension/support.js:13,73`).
- **Permissions (AMO)**: `nativeMessaging, tabs, activeTab, <all_urls>, webRequest, storage`; data collection `none`.
- **Tools** (README): create window, navigate, get content, click (CSS selector), type, press key, screenshot (annotated), tabs list/close, **attach to existing user tabs**, accessibility snapshot, page state + diff, element info, wait-for, scroll, consent-banner auto-dismiss, domain allowlist, private-mode toggle, "focus loops". No file upload found in the README list; JS evaluation via `new Function` in the isolated world (`content.js:1168`).
- **Detectability**: content script on `<all_urls>` at `document_idle` (isolated world; not visible to page JS). On driven tabs it inserts `div#claudezilla-watermark` and `#claudezilla-focusglow-styles` (`content.js:269`, `:328`) — page-detectable; `hideWatermark` only sets opacity 0. [#9](https://github.com/boot-industries/claudezilla/issues/9) (open): clicks are untrusted, click-only events.
- **Flatpak**: needs the native-messaging proxy path (§Flatpak). Its installer targets only `~/.mozilla` — that is in fact where x-n-m-p reads host manifests, so it would work once x-n-m-p is set up.
- **Other issues**: [#20](https://github.com/boot-industries/claudezilla/issues/20) idle agent's tabs closed after 10 min; [#19](https://github.com/boot-industries/claudezilla/issues/19) page-state truncation; [#24](https://github.com/boot-industries/claudezilla/issues/24) Windows installer.

## 3. Blueprint MCP for Firefox

- **AMO**: https://addons.mozilla.org/en-US/firefox/addon/blueprint-mcp-for-firefox/ — signed. 94 users, 5.0 (1 review), 1.9.22 released 2026-08-10, created 2025-11-03, compat ≥ 109, AMO licence **MIT** while the repo says **Apache-2.0** ([AMO API](https://addons.mozilla.org/api/v5/addons/addon/blueprint-mcp-for-firefox/); [repo](https://github.com/railsblueprint/blueprint-mcp)).
- **Owner**: Rails Blueprint (GitHub org, commercial — sells a PRO tier). Repo 102 stars, last push 2026-08-10, 9 open issues. npm `@railsblueprint/blueprint-mcp` 1.9.22 (2026-08-10), 27 versions, 310 downloads/month, deps include `sharp`, has a `postinstall` (prints links only) ([registry](https://registry.npmjs.org/@railsblueprint/blueprint-mcp)).
- **Architecture**: MCP server opens `ws://127.0.0.1:5555`; extension connects. PRO tier swaps this for a **cloud relay** (multi-browser, remote) and an OAuth login against `mcp-for-chrome.railsblueprint.com` (README "Free vs PRO"; `server/src/oauth.js:36`). Free mode makes no outbound calls from the server unless PRO tokens are stored (`statefulBackend.js:59`). **The local WS server has no Origin check and no token: first client to connect wins** (`server/src/extensionServer.js:55–90`) — any web page you have open can `new WebSocket('ws://127.0.0.1:5555')` while the extension is disconnected and receive the agent's commands.
- **Permissions (AMO)**: `tabs, activeTab, webNavigation, webRequest, storage, management, scripting, alarms`; hosts `<all_urls>, *://*.railsblueprint.com/*, *://*.blueprintmcp.com/*`. MV3.
- **Tools** (README): enable/disable/status/auth, tabs (incl. attach), navigate/back, snapshot, screenshot, console, network list/details/**replay with original auth headers**, extract markdown, interact (batched), click, type, hover, select, fill form, press key, drag, evaluate, dialogs, file upload, window, PDF save, perf metrics, verify text/element. Closest to Playwright MCP's names.
- **Detectability**: content script on every page at `document_start` (`extensions/firefox/manifest.json`) runs a `MutationObserver` for `.mcp-extension-tokens` / `.mcp-extension-focus-tab` on **every site** (`src/content-script.js:30–75`) — any page can plant those elements to focus itself or push login tokens into the extension. On the attached tab it injects into the **MAIN world**: overrides `console.*` and `alert/confirm/prompt`, sets `window.__blueprintConsoleInjected` / `window.__originalPrompt` (`shared/handlers/console.js:121–159`, `shared/handlers/dialogs.js:109`) — trivially page-detectable (`console.log.toString()` is no longer native).
- **Firefox health**: [#49](https://github.com/railsblueprint/blueprint-mcp/issues/49) (open since 2026-08-05) "Firefox 153: extension background fails to start — never connects… (works on <= Firefox 134)"; maintainer says a CSP fix (#48) landed and asked for a retest, no confirmation. [#41](https://github.com/railsblueprint/blueprint-mcp/issues/41) (open) "Newest Firefox doesn't support some CDP methods" (`Accessibility.getFullAXTree`). [#31](https://github.com/railsblueprint/blueprint-mcp/issues/31) earlier "Firefox extension does not work".
- **Claude Code setup** (README): `claude mcp add browser npx @railsblueprint/blueprint-mcp@latest` — unpinned `@latest`.
- **Flatpak**: none (localhost WS).

## 4. ClaudeCodeBrowser (nanogenomic)

- **AMO**: https://addons.mozilla.org/en-US/firefox/addon/claudecodebrowser/ — signed. **2,243 users, 0 ratings**, only version 1.0.0 (2025-12-13, last updated 2025-12-16), compat ≥ 78, MIT ([AMO API](https://addons.mozilla.org/api/v5/addons/addon/claudecodebrowser/)). The repo is at 1.4.0 and its manifest carries `update_url` → GitHub releases (`extension/manifest.json`), but the repo has **no GitHub releases** (`gh api repos/nanogenomic/ClaudeCodeBrowser/releases` = empty) — so AMO users are stuck on 1.0.0.
- **Owner**: Andre Watson / Ligandal Inc. (README). Repo https://github.com/nanogenomic/ClaudeCodeBrowser, MIT, 107 stars, last push 2026-08-26.
- **Architecture**: Python MCP server with HTTP :8765 + WS :8766; extension **polls `localhost:8765/browser/poll` every 500 ms**; native messaging host optional for disk/clipboard (README "Architecture"). Also a Playwright headless mode. Install script writes `~/.mozilla/native-messaging-hosts` only; README tells you to load the extension as a *temporary* add-on.
- **Permissions (AMO)**: `activeTab, tabs, nativeMessaging, storage, <all_urls>, webNavigation, contextMenus`.
- **Detectability**: content script **and CSS** injected into every page, all frames, at `document_end` (`extension/manifest.json`); the CSS defines `@keyframes claude-pulse`, `.claude-highlight-overlay`, `.claude-inspector-mode` (`extension/content.css`) — a page can probe those class names to detect the add-on on any site. Logs `[ClaudeCodeBrowser] Content script loaded` to every page's console.
- **Tools**: screenshot, click (selector/XPath/text/coords), type, scroll, navigate, tabs, JS exec, console/network logging, safety guards (README "Features"). No accessibility snapshot with refs.

## §Flatpak: native messaging on Firefox 157

Firefox 157 ships the frontend for `xdg-native-messaging-proxy` ([bug 1955255](https://bugzilla.mozilla.org/show_bug.cgi?id=1955255): RESOLVED FIXED, `cf_status_firefox157: fixed`), **disabled by default**. A working recipe from 2026-10-02 ([x-n-m-p #9 comment](https://github.com/flatpak/xdg-native-messaging-proxy/issues/9)):
1. Host: `rpm-ostree install xdg-native-messaging-proxy` + reboot (Fedora 44 package `xdg-native-messaging-proxy-0.1.0-1.fc44` is available; on an image-based system it belongs in the image build).
2. `flatpak override --user --talk-name=org.freedesktop.NativeMessagingProxy org.mozilla.firefox`
3. `about:config` → `widget.use-xdg-desktop-portal.native-messaging-proxy` = `2`.
Host manifests stay in host `~/.mozilla/native-messaging-hosts`; the host binary runs **outside** the sandbox (x-n-m-p spawns it). The x-n-m-p README warns this proxy is "potentially *INSECURE*" as a sandbox hole ([README](https://github.com/flatpak/xdg-native-messaging-proxy)). Net: Claudezilla and ClaudeCodeBrowser are feasible but cost an OS-image change, a Flatpak override and a hidden pref; localhost-WS designs cost nothing.

## Ranking

| Rank | Candidate | Trust | Maintenance | Capability | Zero-detectability | Flatpak setup |
|---|---|---|---|---|---|---|
| 1 | FoxPilot | medium: one individual, MIT, small codebase, zero npm deps; you can read and pin it | high (daily commits) but AMO lags repo | high (Playwright-like uid snapshot, upload, eval, network) | best: no persistent injection | none |
| 2 | Claudezilla | medium: small org, MIT, Unix-socket + token | medium (last push 2026-08-07) | high, minus upload | good on unrelated pages; watermark on driven tabs | high |
| 3 | Blueprint MCP | low–medium: commercial upsell, unauthenticated local WS, every-page DOM token watcher | medium; open Firefox-breakage issues | highest feature count | poor on driven tabs (MAIN-world overrides) | none |
| 4 | ClaudeCodeBrowser | low: AMO build frozen at 1.0.0, 2,243 users/0 reviews | AMO abandoned | medium | poor (CSS + script in all frames everywhere) | medium–high |

**#1: FoxPilot.** Deciding reason: it is the only candidate that combines an AMO-signed permanent install, a full Playwright-style action set, **no persistent content script or page-world globals**, and a pure localhost-WebSocket transport that works in the Flatpak today with no OS change. Set `EXTENSION_SECRET` (closes the any-extension-origin pairing) and pin the npm version instead of `npx -y foxpilot-mcp`.

**What would flip it:**
- If the single-maintainer, fast-churning, AI-written codebase is the sticking point: take the same code (or foxcode, or eyalzh + automation) and **self-sign it as an unlisted add-on under your own AMO account** (`web-ext sign --channel=unlisted`, see [signing overview](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/)). That gives a permanent install in release Firefox with code you have reviewed and no third-party auto-update. This is the trust-maximal path and would beat every listed option on trust.
- If FoxPilot's open disconnect bug (#4) or the upstream permission-bypass (#66) reproduces, Claudezilla becomes #1 — after the three x-n-m-p steps.

**Rule out outright:** Browser MCP (no Firefox; AMO "Browser MCP" is an unattributed lookalike), Blueprint MCP for daily-browser use (unauthenticated `ws://127.0.0.1:5555` any web page can grab, every-page DOM token listener, MAIN-world console/dialog overrides, unresolved Firefox ≥ 153 startup bug), ClaudeCodeBrowser (AMO copy frozen at 1.0.0 since Dec 2025, CSS+script injected into every frame of every site), mcp-browser-kit (no auth), Element to LLM MCP (mandatory cloud relay + account).
